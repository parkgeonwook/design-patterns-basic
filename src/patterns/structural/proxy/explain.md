# 프록시
핵심은 실제 객체 앞에서 접근을 대신 관리하는 것

대리 객체가 접근 제어, 관리

대신 생성, 대신 검사, 대신 로그, 대신 원격 호출...

---

(아래 설명은 특징 중 하나일뿐. 프록시의 핵심 기능 하나인 것은 아님. "대신"이 핵심)
## 프록시를 사용하지 않을 때
### 실제 객체를 바로 생성하면서 무거운 작업도 함께 실행된다.

`RealImage image = new RealImage("photo.png");` 객체를 생성하는 순간 바로 이미지 로딩이 일어난다.

아직 이미지를 출력하지 않아도 미리 로딩하게 된다.

즉, 실제로 사용할지 확실하지 않은데도 비용이 큰 작업이 먼저 실행될 수 있다.

## 프록시를 사용할 때
### 실제 객체를 바로 만들지 않고, 필요할 때만 생성할 수 있다.

`Image image = new ProxyImage("photo.png");` 이 시점에는 실제 이미지가 아직 로딩되지 않는다.

이후 `image.display();`를 호출하는 순간 프록시가 내부에서 `RealImage`를 생성하고, 이미지를 로딩한 뒤 출력한다.

즉, 실제 사용 시점까지 무거운 작업을 미룰 수 있다.

지연 로딩 같은 느낌.

진짜 사용할 때 필요한 작업 처음 준비하니까 첫 호출은 더 느릴 수 있을듯.

당장 느리냐 빠르냐 보다 정말 필요할 때만 비용 쓰는 느낌
